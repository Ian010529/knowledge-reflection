# Blinded source-grounded evaluation

You are a fresh Astra evaluator. Read ONLY this file, protocol.md, your assigned blind/<domain>.json, and your own work/judge_<domain> directory. Do NOT read private/, extraction or reference author directories, other judge outputs, parent history, previous scores or author notes. No API/network/subagents. The packet contains full original abstracts, anonymous candidate relations and an independently source-authored reference set. Versions are deliberately hidden. Evaluate against original text, not expectation of improvement or a target score.

Each candidate: label `supported`, `partial`, `unsupported`, `uncertain`, or `out_of_scope`. Correctness means the entire relation including actual endpoints, direct attribution, direction, assertion strength, evidence modality, material identity, necessary conditions and joint factors is supported. Generic narrative or numbers alone are not mechanistic relations. Explicit scope-defined structural attributes and physical interactions are legitimate. Do not penalize a faithful paraphrase or alternative role merely because it differs from reference; record consequential role errors. Preserve legitimate empirical ability statements with can; do not blanket mark them hypotheses. Single-datum measurements and explicit extremum/comparison relations differ. Report a compact concrete Chinese reason for EVERY label (supported can briefly cite source logic). Error tags can be endpoint/direction/modality/condition/joint_factor/inferred_link/scope/granularity/source_ambiguous/none.

Each reference: judge `valid`, `uncertain`, or `out_of_scope` using source and frozen scope. If it overstates causality or invents an effect, mark uncertain with reason rather than forcing candidates to imitate it. For valid references, give complete and partial coverage by candidate IDs. Full coverage must preserve necessary qualifiers and direct relationship; a path or a phrase inside a longer node is insufficient. One compound candidate can cover multiple explicit result references if all meanings are retained. Multiple candidates may jointly cover a reference ONLY when the common attribution/conditions are actually represented; separate independent effects do not recover a joint claim.

Output `judgments.json` array with every input paper once:

```
{"paper_id":"P...", "candidates":[{"candidate_id":"C...","label":"supported","error_tags":["none"],"reason":"..."}], "references":[{"reference_id":"G...","label":"valid","reason":"...","full_coverage_sets":[["C1"],["C2","C3"]],"partial_candidates":["C4"]}], "note":"remaining source ambiguity / source-only observation"}
```

An OR of full_coverage_sets means any ONE set fully covers reference; within a set every ID is required. Use [] if absent. Usually each set has one ID. Do not use a candidate labelled unsupported/uncertain/out_of_scope for full coverage. `partial` candidates can fully cover a narrower valid reference while having an additional error; explain this explicitly. Never put full_coverage_sets on an invalid reference.

Evaluate every candidate and every reference, including empty arrays. Do not infer labels using keyword/Python similarity. You may author judgment batches in your own directory then concatenate; Python only validates IDs, schemas and exact count coverage. Do not rewrite reference or extraction. If reference missed a valid candidate claim, note that absence; do not extend reference denominator in this test. Return file path, counts, protocol isolation declaration, and any issues. Do NOT report which version did better (you do not have that information).
